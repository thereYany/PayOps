# PayOps

虚拟支付订单系统的高可用、性能与运维演进教学项目。

## 最终目的

交付一个虚拟支付的订单支付系统，最终形态稳定、高性能、高可用；同时保留从粗糙版本到最终版本的完整演进时间线，让每个问题都能被触发、观察、解释和修复。

## 教学方式

- 第一版故意保留典型缺陷，不追求一开始就正确。
- 前端提供可点击的测试场景，直接触发问题：并发下单、重复支付、容器故障、压测过载等。
- 每个问题按统一链路展开：触发 → 现象 → 指标与日志 → 原因 → 修复 → 再验证 → 面试讲法。
- 修复前后都可以运行，历史阶段可以回放，而不是只在文档里描述。

## 时间线

最终形态完成之后，时间线仍然可以回放。每个阶段都有对应的代码、配置、数据和部署状态，可以从任意阶段重现当时的错误，再切换到修复后的阶段对比结果。

时间线不是文档叙述，而是可运行的软件状态。

## 第一课：超卖

粗糙版本采用“先查库存再扣减”的实现，前端一键并发购买，稳定复现超卖。

随后逐步引入原子扣减、数据库锁或乐观锁、幂等、队列与限流等修复，并用指标证明修复有效。

## 后续主题

- 重复支付与回调幂等
- 订单、支付、权益的一致性
- 超时、补偿与对账
- 缓存、索引与性能优化
- 压测与容量预算
- 多容器与负载均衡
- 故障切换与滚动发布
- 监控、告警与恢复演练

## 约束

- 只做虚拟支付，不接真实支付渠道。
- 目标运行环境为 4C4G，组件数量、内存和容器规格按此预算。
- 单机多容器先演示容器与进程级高可用；主机级故障边界会在课程中明确说明。

## 成功标准

学习者能亲手复现每个问题，讲清楚它为什么发生、怎么修复、修复的代价是什么，并能把整条演进时间线完整讲给面试官。
